# Kelisim — как устроен проект (шпаргалка для защиты)

Этот файл объясняет, **что** мы построили, **как** оно работает внутри и **почему** выбраны именно эти решения. Последний раздел — список вероятных вопросов с готовыми ответами.

---

## 1. Проект за 30 секунд

**Kelisim** — веб-сервис для малого бизнеса Казахстана, который торгует с Китаем, Турцией и другими странами. Проблема: юрист стоит до 150 тыс. ₸ за договор, шаблоны из чатов не учитывают валютный контроль РК, а реальные потери происходят после подписания — забыли получить УНК, просрочили репатриацию, поставщик оказался под санкциями и банк заблокировал платёж.

Три ключевые функции:

1. **Документы** — пошаговая форма (мастер из 4 шагов) → пакет из 4 документов (договор, спецификация, инвойс, упаковочный лист) на двух языках: RU/CN или RU/EN, колонками рядом. Скачивание в DOCX или печать в PDF.
2. **Проверка рисков (compliance)** — поставщик сверяется с реальными санкционными списками OFAC (США), ЕС и Великобритании; считается, нужен ли УНК (порог 50 000 USD по официальному курсу Нацбанка на дату подписания); рассчитывается срок репатриации. Результат — светофор: зелёный / жёлтый / красный.
3. **Трекер сроков** — после скачивания документов автоматически создаются дедлайны (УНК, оплата, поставка, репатриация), календарь, напоминания в Telegram и на email за 7, 3, 1 день и при просрочке, загрузка подтверждающих файлов (выписка банка и т. п.).

Плюс: регистрация/вход, онбординг с проверкой БИН, контрагенты, тарифы (Free — 2 пакета в месяц), демо-кабинет в один клик, RU/EN интерфейс, тёмная тема, мобильная версия, установка как приложение (PWA).

## 2. Общая архитектура

```
 Браузер (React SPA)                       Cloudflare (edge, ~300 городов)
 ┌───────────────────────┐   HTTPS   ┌─────────────────────────────────────────┐
 │ React 19 + Router 7   │ ────────▶ │ Worker "kelisim"                        │
 │ - страницы, мастер    │           │  ├─ /api/*  → Hono (наш API, TypeScript) │
 │ - генерация документов│ ◀──────── │  └─ всё остальное → Static Assets        │
 │   (shared/documents)  │   JSON    │       (собранный React из ./dist)        │
 │ - DOCX (библиотека    │           │                                          │
 │   docx), печать в PDF │           │  Привязки (bindings):                    │
 └───────────────────────┘           │   DB      → D1 (SQLite) kelisim-db       │
                                     │   ASSETS  → статические файлы            │
                                     │   PROOFS  → R2 (опционально, файлы)      │
                                     │  Cron 03:00 UTC → курсы + напоминания    │
                                     └──────────────┬──────────────────────────┘
                                                    │ fetch
           ┌────────────────────────────────────────┼──────────────────────┐
           ▼                    ▼                   ▼                      ▼
  nationalbank.kz RSS   Telegram Bot API     Resend (email)    GitHub Actions (вне Worker):
  (курсы валют)         (напоминания)                          ежедневный импорт OpenSanctions
                                                               → D1 через wrangler
```

**Ключевая идея:** один Worker отдаёт и сайт, и API. Нет отдельного сервера, нет отдельного хостинга фронтенда, нет отдельной базы на другом сервисе — всё в одном аккаунте Cloudflare, одной командой `npm run deploy`.

## 3. Почему Cloudflare

| Причина | Объяснение |
|---|---|
| **Бесплатно для MVP** | Free-план Workers: 100 000 запросов в день; D1: 5 ГБ и миллионы чтений; статика бесплатна и не считается в запросы. Для учебного проекта и первых пользователей — 0 ₸. |
| **Один сервис — всё** | Хостинг фронтенда, сервер API, база данных (D1), файловое хранилище (R2), расписание (Cron Triggers) — в одном месте. Не нужно связывать Vercel + Heroku + Supabase. |
| **Edge = быстро** | Код запускается в дата-центре, ближайшем к пользователю (есть точки в Алматы и рядом), нет «холодного старта» в секунды как у классических serverless — Workers стартуют за миллисекунды (V8 isolates, а не контейнеры). |
| **Нет администрирования** | Не надо настраивать сервер, Linux, nginx, SSL-сертификаты, обновления — HTTPS и масштабирование автоматически. |
| **Простой деплой** | `wrangler deploy` за ~10 секунд; можно повесить на push в GitHub. |

**Минусы, которые стоит знать (и честно назвать, если спросят):**
- Ограничение CPU на запрос (на бесплатном плане ~10 мс CPU) — поэтому тяжёлый импорт санкционных списков вынесен в GitHub Actions.
- D1 — это SQLite: одна «основная» база, не для огромных нагрузок с тысячами записей в секунду; для MVP и SMB-сегмента этого с запасом.
- Привязка к вендору (vendor lock-in) — частично снята: бизнес-логика лежит в папке `shared/` и не зависит от Cloudflare; Hono тоже работает на Node/Bun/Deno.

**Альтернативы, которые мы рассматривали:** Vercel + Supabase (два сервиса, лимиты, фронт и бэк раздельно), VPS (дешево, но надо администрировать, нет автоскейлинга), Firebase (NoSQL — неудобно для связанных данных сделок, дедлайнов, контрагентов).

### Сервисы Cloudflare, которые мы используем

- **Workers** — серверный JavaScript/TypeScript, запускается на каждый запрос. Наш файл входа — `worker/index.ts`.
- **Workers Static Assets** — раздаёт собранный фронтенд из папки `dist/`. Настройка `not_found_handling = "single-page-application"` означает: если файла нет (например `/app/deals/123`), отдаётся `index.html`, и дальше маршрут обрабатывает React Router. `run_worker_first = ["/api/*"]` — запросы к API сначала идут в наш код.
- **D1** — управляемая SQLite-база. Подключена как привязка `DB`, в коде: `c.env.DB.prepare("SELECT ...").bind(...).all()`.
- **R2** — объектное хранилище (аналог Amazon S3) для файлов-подтверждений до 10 МБ. Опционально: без него файлы до 1 МБ хранятся прямо в D1 как BLOB.
- **Cron Triggers** — `crons = ["0 3 * * *"]`: каждый день в 03:00 UTC (08:00 по Астане) Worker сам запускается, обновляет курсы и рассылает напоминания.
- **Wrangler** — CLI Cloudflare: локальный запуск (`wrangler dev`), миграции базы, деплой, секреты.

Конфигурация всего этого — один файл `wrangler.toml`.

## 4. Технологический стек и почему

| Слой | Технология | Почему |
|---|---|---|
| Язык | **TypeScript** везде (фронт, бэк, тесты, скрипты) | Один язык; типы `DealInput`, `ComplianceResult` общие для клиента и сервера — меньше ошибок на стыке. |
| Фронтенд | **React 19** + **React Router 7** | Стандарт индустрии, SPA с множеством экранов (кабинет, мастер, календарь). |
| Сборка | **Vite** | Быстрая сборка и hot-reload при разработке. |
| API | **Hono** | Маленький (~14 КБ) веб-фреймворк, сделан под Workers; синтаксис как у Express: `app.get("/api/deals", ...)`. |
| База | **Cloudflare D1** (SQLite) | Реляционные данные (пользователь → сделки → дедлайны → файлы), SQL, внешние ключи, полнотекстовый поиск FTS5. |
| Документы | библиотека **docx** (в браузере) | Генерация настоящего Word-файла без сервера. |
| Иконки | lucide-react | Лёгкие SVG-иконки. |
| QR | qrcode | QR-код для привязки Telegram-бота. |
| Тесты | **Vitest** (unit) + **Playwright** (e2e в реальном браузере) | Vitest быстрый и совместим с Vite; Playwright проходит весь путь пользователя. |
| CI/CD | **GitHub Actions** | Автодеплой при push и ежедневный импорт санкций. |
| Почта | **Resend** | Простой HTTP API для писем (сброс пароля, напоминания). |
| Мессенджер | **Telegram Bot API** | В Казахстане бизнес живёт в Telegram/WhatsApp; у Telegram бесплатный и простой Bot API. |

Никаких тяжёлых UI-библиотек (Material, Bootstrap) — свой CSS с переменными (design tokens) по макетам Figma; это же позволило сделать тёмную тему переключением переменных.

- одна и та же логика работает и в браузере (мгновенный предпросмотр документов), и на сервере (проверка, которой можно доверять);
- её легко тестировать — тесты не нуждаются в базе или интернете;
- её можно перенести на другую платформу без переписывания.

## 6. Как проходит запрос (на примере «Проверить сделку»)

1. Пользователь на шаге проверки нажимает «Проверить». React вызывает `api.post("/deals/<id>/check")` (`src/api.ts`) — обычный `fetch` на `/api/deals/<id>/check` с cookie сессии.
2. Cloudflare принимает запрос в ближайшем дата-центре. Путь начинается с `/api/` → запускается Worker (`run_worker_first`).
3. Hono в `worker/index.ts` направляет его в `worker/routes/deals.ts`.
4. Middleware авторизации читает cookie, хеширует токен SHA-256, ищет сессию в таблице `sessions` → получаем пользователя.
5. Загружается сделка из D1 (`deals.data_json`), проверяется, что она принадлежит этому пользователю.
6. `worker/lib/external.ts`:
   - `sanctionsFor()` — ищет кандидатов в полнотекстовом индексе `sanctions_fts` (до 200 записей) + демо-записи;
   - `ratesFor()` — берёт курс НБРК на дату подписания (из кэша `fx_rates`, иначе скачивает RSS Нацбанка; при недоступности — демо-курс с пометкой).
7. `checkDeal()` из `shared/compliance.ts` считает три проверки и общий цвет.
8. Результат сохраняется в `deals.check_json`, `risk`, добавляется событие в `deal_events`.
9. Ответ JSON → React показывает анимацию трёх проверок и результат-светофор.

Ошибки: бизнес-ошибки бросаются как `ApiError(код, статус)` и превращаются в JSON `{ error: "plan_limit" }`; фронт переводит код в текст на нужном языке (`errText`).

## 7. База данных (D1 / SQLite)

Схема — в `migrations/0001_init.sql` и `0002_real_data_files_email.sql`. Миграции применяются по порядку командой `wrangler d1 migrations apply` (она входит в `npm run deploy`), Cloudflare помнит, какие уже применены.

| Таблица | Что хранит |
|---|---|
| `users` | логин (email или телефон), хеш и соль пароля, имя, язык, тариф, шаг онбординга, Telegram chat_id, email и флаг напоминаний |
| `sessions` | **хеш** токена сессии, пользователь, срок действия |
| `password_resets` | хеш токена сброса пароля |
| `companies` | реквизиты компании пользователя: БИН, форма (ИП/ТОО), названия, адрес, подписант, банк, БИК, IBAN |
| `counterparties` | поставщики/покупатели: название, название на местном языке, страна, адрес, банк, результат последней проверки |
| `deals` | сделка: номер KLS-001, статус (draft/checked/active/closed), риск, **data_json** (все поля мастера), check_json, УНК, сумма, валюта |
| `deadlines` | дедлайны сделки: тип (ucn/payment/delivery/repatriation), дата, выполнено, заметка, «отложить до», когда последний раз напоминали |
| `deal_events` | история сделки (создана, проверена, документы, УНК, выполнен дедлайн…) |
| `usage` | счётчик скачанных пакетов по месяцам — для лимита тарифа Free |
| `sanctions_entities` | импортированные санкционные организации: список, имя, псевдонимы, страны, программа |
| `sanctions_fts` | **FTS5**-индекс по именам для быстрого поиска |
| `sanctions_meta` | версия и дата загруженных списков |
| `fx_rates` | кэш курсов НБРК по датам |
| `proof_files` | файлы-подтверждения: имя, тип, размер, где хранится (r2/d1), сами байты если в D1 |

**Почему `data_json`, а не 30 колонок?** Форма сделки большая и вложенная (стороны, товары списком, условия). Храним её целиком JSON-ом, а то, по чему нужно искать и сортировать (статус, риск, сумма, валюта, контрагент), — отдельными колонками. Это компромисс между гибкостью и возможностью делать запросы.

**Почему FTS5 «contentless»?** Списки — десятки тысяч организаций с псевдонимами. Полнотекстовый индекс находит кандидатов за миллисекунды, а точное сравнение похожести делаем уже в коде только по ~200 кандидатам. `content=''` — индекс не дублирует текст, экономит место.

Связи: всё привязано к `user_id` с `ON DELETE CASCADE` — удаление пользователя удаляет его данные. Каждый запрос в API фильтрует по `user_id`, чтобы пользователь не увидел чужие сделки.

## 8. Как работают три ключевые функции

### 8.1. Генерация документов

- Мастер из 4 шагов (`src/pages/Wizard.tsx`): 1) тип договора и языковая пара, 2) контрагент, 3) товары и сумма, 4) условия (Incoterms, оплата, даты). Черновик автоматически сохраняется на сервер; ошибки показываются у поля (`validateDeal` — одна функция для фронта и сервера).
- `shared/documents.ts` → `generatePackage()` превращает данные сделки + реквизиты компании в 4 документа: **договор, спецификация, инвойс, упаковочный лист**. Каждый пункт — пара текстов на двух языках (тип `Bi`), с правильными падежами в русском («покупателя», «покупателем» — для этого словарь форм ролей).
- Генерация идёт **в браузере**: предпросмотр мгновенный, переключение RU / CN / двуязычно, панель «изменить пункт» (например, оплата 30% предоплаты) пересобирает весь пакет сразу.
- Скачивание: DOCX через библиотеку `docx` (двуязычный режим — таблица из двух колонок), или PDF через печать браузера (`printDocs`).
- При скачивании фронт вызывает `POST /api/deals/:id/generate`: сервер проверяет лимит тарифа, увеличивает счётчик `usage`, переводит сделку в «active» и **создаёт дедлайны**.
- Если проверка красная (санкции) — генерация заблокирована.

*Почему в браузере, а не на сервере:* экономим CPU Worker'а (лимит), не храним готовые файлы, пользователь видит изменения сразу. Сервер всё равно контролирует бизнес-правила (лимит, блокировка при красном риске, дедлайны).

### 8.2. Проверка рисков (compliance) — `shared/compliance.ts`

Три проверки, каждая даёт green / yellow / red, общий цвет = худший:

**1) Санкции контрагента** (`screenCounterparty`)
- Название нормализуется: нижний регистр, убираем знаки и юр. формы (Co., Ltd., LLC, ТОО…).
- Сравнение с каждым кандидатом: **похожесть = максимум из** (а) коэффициента Жаккара по словам и (б) 1 − расстояние Левенштейна / длина. Сравниваются основное имя и все псевдонимы, а также название на местном языке.
- ≥ 0.85 → **красный** (совпадение, документы блокируются); ≥ 0.65 → **жёлтый** («похоже, банк может спросить»); иначе зелёный. Учитывается и страновой риск.
- Источник: реальные списки OFAC SDN, EU FSF, UK (через OpenSanctions) + несколько вымышленных демо-записей (например «Shenzhen Redline Electronics Co., Ltd.»), чтобы на демо показать красный сценарий. Демо-записи отключаются переменной `DEMO_SANCTIONS="off"`.

**2) УНК (учётный номер контракта)**
- Правило валютного контроля РК: экспортный/импортный контракт на сумму **больше 50 000 USD в эквиваленте** надо зарегистрировать в банке и получить УНК до первой оплаты/отгрузки.
- Сумма пересчитывается в USD **по официальному курсу НБРК на дату подписания** (`toUsd`, курсы — через тенге). Договор без суммы — УНК нужен.
- Если нужен → жёлтый «Подайте договор в банк…», кнопка открывает окно ввода УНК; после ввода пункт становится зелёным (`applyUcn` на сервере пересчитывает итог).

**3) Репатриация**
- Если деньги уходят до получения товара (предоплата), товар должен поступить (или деньги вернуться) к **дате исполнения** обязательств. Срок длиннее **180 дней** → предупреждение «длинный срок репатриации».
- При постоплате репатриация не контролируется.

В результат записываются `rules_version`, версия санкционных списков и источник/дата курса — видно, на основании каких данных принято решение (важно для доверия и аудита).

### 8.3. Трекер сроков

- `buildDeadlines()` создаёт:
  - **оплата**: при предоплате = дата подписания + 5 дней; при постоплате = дата поставки + N дней отсрочки;
  - **УНК** (если нужен): до более ранней из дат — оплата или поставка;
  - **поставка**: дата поставки;
  - **репатриация** (если не постоплата): дата исполнения.
- Экраны: дашборд (баннер просрочек, «нужен УНК»), календарь, вкладка «сроки» в сделке, колокольчик уведомлений.
- Действия: «выполнено» с заметкой и файлом-подтверждением (PDF/PNG/JPEG/WEBP/HEIC; до 1 МБ в D1 или до 10 МБ в R2), «отложить».
- **Напоминания** (`worker/lib/telegram.ts`, функция `shouldRemind`): cron раз в день проверяет все невыполненные дедлайны — напоминание уходит, если осталось **7, 3, 1 или 0 дней** либо срок просрочен; не чаще раза в день (`last_notified`), с учётом «отложено до». Канал — Telegram (тариф Pro) и/или email.

## 9. Внешние данные

### OpenSanctions (санкционные списки)
- Используем открытые выгрузки `targets.simple.csv` для датасетов `us_ofac_sdn`, `eu_fsf`, `gb_fcdo_sanctions`, `gb_hmt_sanctions` (лицензия CC BY-NC — некоммерческое использование; для коммерческого запуска нужна платная лицензия, это в ограничениях).

### Национальный банк РК (курсы)
- RSS `https://nationalbank.kz/rss/get_rates.cfm?fdate=ДД.ММ.ГГГГ` — XML с курсами к тенге (с учётом `quant`, например за 100 единиц).
- Курс кэшируется в `fx_rates`; cron каждое утро подтягивает курс на сегодня.
- Если сайт недоступен — используется фиксированный демо-курс, и в результате это честно помечено «демо-курс».

### Поиск компании по БИН
- Проверяется контрольная цифра БИН/ИИН по официальному алгоритму (`shared/bin.ts`). Сам реестр — демо-заглушка; в продакшене — API stat.gov.kz / egov (указано в ограничениях).

## 10. Аутентификация и безопасность

- **Пароли:** PBKDF2-SHA256, 100 000 итераций (максимум, доступный в Workers WebCrypto), уникальная соль на пользователя. Пароль нигде не хранится в открытом виде.
- **Сессии:** случайный 32-байтный токен в cookie `HttpOnly` (JS не может прочитать → защита от кражи через XSS), `SameSite=Lax` (защита от CSRF), `Secure` на HTTPS. В базе хранится **только SHA-256 хеш токена** — утечка базы не даёт войти. «Запомнить меня» — 30 дней, иначе 1 день.
- **Сброс пароля:** одноразовый токен (тоже хешируется), с ограниченным сроком; письмо через Resend, а если почта не настроена — ссылка показывается на экране (демо-режим).
- **Изоляция данных:** каждый SQL-запрос содержит `WHERE user_id = ?`; доступ к чужой сделке/файлу → 404.
- **SQL-инъекции:** только параметризованные запросы `prepare(...).bind(...)`.
- **Валидация:** `sanitizeDeal` на сервере приводит вход к ожидаемым типам — сервер не доверяет фронту. Проверка типов и размера загружаемых файлов.
- **Секреты** (токен бота, ключ Resend) — через `wrangler secret put`, не в коде. Telegram webhook защищён секретным заголовком.
- **API не кэшируется** (`Cache-Control: no-store`).

- **Демо-кабинет** — `/demo` создаёт временного пользователя с тарифом Pro и заполненными сделками (зелёная, жёлтая с УНК, просроченный дедлайн) — показать продукт без регистрации.

## 16. Вероятные вопросы и ответы

**Почему Cloudflare, а не обычный сервер?**
Бесплатно на старте, всё в одном месте (хостинг, сервер, база, файлы, расписание), не нужно администрировать сервер, быстрые ответы с ближайшего дата-центра, деплой одной командой. Минус — лимит CPU, его обошли вынесением импорта в GitHub Actions.

**Что такое Worker?**
Функция на JavaScript/TypeScript, которую Cloudflare запускает на каждый HTTP-запрос в своих дата-центрах. Не контейнер и не виртуальная машина, а изолят движка V8 (как вкладка браузера) — стартует за миллисекунды.

**Где у вас бэкенд, где фронтенд?**
Один Worker: `/api/*` обрабатывает наш код на Hono (папка `worker/`), всё остальное — статика React (папка `src/`, собранная Vite в `dist/`). Общая логика — в `shared/`.

**Что такое D1? Почему SQL, а не NoSQL?**
D1 — SQLite-база, которой управляет Cloudflare. Данные связанные (пользователь → компания, сделки → дедлайны → файлы), нужны JOIN, внешние ключи, каскадное удаление, полнотекстовый поиск — это реляционная модель.

**Как вы проверяете санкции? Это реальные данные?**
Да: OFAC SDN (США), EU и UK — из открытого агрегатора OpenSanctions, обновляются ежедневно через GitHub Actions. Кандидатов находим полнотекстовым индексом FTS5, потом считаем похожесть названий (Жаккар по словам и Левенштейн), ≥85% — красный, ≥65% — жёлтый. Для демонстрации добавлены несколько вымышленных записей.

**Почему импорт санкций не в самом Worker?**
Файлы — несколько мегабайт CSV, разбор превышает лимит CPU бесплатного Worker'а. GitHub Actions — бесплатная машина с Node.js, которая готовит SQL и загружает его в D1 через Wrangler.

**Откуда курс валют?**
Официальный RSS Нацбанка РК на дату подписания договора; кэшируется в базе; при недоступности — демо-курс с явной пометкой.

**Как считается, нужен ли УНК?**
Сумма договора переводится в доллары по курсу НБРК на дату подписания; если больше 50 000 USD — нужен УНК, срок — до первой оплаты или поставки.

**Как хранятся пароли?**
PBKDF2-SHA256, 100 000 итераций, соль. Сессия — случайный токен в HttpOnly-cookie, в базе только его хеш.

**Где генерируются документы? Почему не на сервере?**
В браузере, общим модулем `shared/documents.ts`, DOCX — библиотекой `docx`. Так предпросмотр мгновенный и не тратится CPU сервера; сервер отвечает за правила (лимит тарифа, блокировка при санкциях, дедлайны).

**Как работают напоминания?**
Cron Trigger раз в день в 08:00 по Астане запускает Worker; он находит дедлайны, до которых 7/3/1/0 дней или которые просрочены, и шлёт сообщение в Telegram-бот и/или на email, отмечая, что сегодня уже напоминали.

**Как вы тестировали?**
37 unit-тестов (логика проверки, документы, разбор реальных CSV/XML), e2e-тест Playwright всего пути пользователя в браузере, аудит мобильной вёрстки, проверка типов TypeScript. В CI деплой идёт только если тесты прошли.

**Что будет, если пользователей станет много?**
Workers масштабируются автоматически. Узкое место — D1 (одна SQLite-база): для SMB-сервиса это тысячи пользователей без проблем; дальше — шардирование по пользователям (у D1 можно много баз) или переход на Postgres (Hyperdrive). Логика в `shared/` от базы не зависит.

**Почему TypeScript везде?**
Одни и те же типы данных на клиенте и сервере, ошибки ловятся при сборке, одна и та же функция валидации работает и в форме, и в API.

**Что такое Hono и почему не Express?**
Express рассчитан на Node.js-сервер; Hono — маленький фреймворк под Web-стандарты (Request/Response), который работает в Workers, при этом синтаксис похож.

**Что такое SPA и `not_found_handling`?**
Single Page Application — браузер один раз загружает приложение, дальше страницы меняет React без перезагрузки. Если открыть прямую ссылку `/app/calendar`, такого файла нет — Cloudflare отдаёт `index.html`, React Router показывает календарь.

**Что такое миграции?**
Пронумерованные SQL-файлы, которые меняют схему базы. Wrangler запоминает применённые и при деплое накатывает только новые — схема одинаковая локально и в проде.

**Что такое PWA?**
Сайт, который можно «установить» на телефон как приложение (иконка, полноэкранный режим, работа офлайн для оболочки) — через manifest и service worker, без App Store.

**Чем ваш продукт лучше юриста или шаблона?**
Дешевле и быстрее (15 минут против дней и 150 тыс. ₸), учитывает валютный контроль РК, а главное — сопровождает сделку после подписания (УНК, репатриация, напоминания), где и случаются реальные потери. Юристы не исключаются — в планах проверка шаблонов юристом.

## 17. Мини-глоссарий

- **УНК** — учётный номер контракта, присваивается банком при регистрации валютного договора > 50 000 USD.
- **Репатриация** — обязанность вернуть в РК валютную выручку или товар/деньги по предоплате в срок.
- **Incoterms** (FCA, FOB, EXW…) — международные правила, кто и где отвечает за доставку и риски.
- **OFAC SDN** — санкционный список Минфина США; **EU FSF** — консолидированный список ЕС; **UK** — список Великобритании.
- **FTS5** — модуль полнотекстового поиска SQLite.
- **Edge** — выполнение кода в ближайшем к пользователю дата-центре.
- **Binding (привязка)** — способ дать Worker'у доступ к ресурсу Cloudflare (база `DB`, статика `ASSETS`, файлы `PROOFS`).
- **CI/CD** — автоматическая проверка и выкладка кода при каждом изменении.
